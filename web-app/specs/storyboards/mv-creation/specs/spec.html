AI Music Video (MV) Creation

Draft ·Version: v1 · Author: Jason Chen · Date: 2026-08-27 ·Guideline: Open ↗

The end-to-end flow to create an AI music video on the web: compose a brief (type, song, description, character photos, output settings), choose storyboard-first or direct generation, watch generation, optionally review and edit a storyboard, view the result, and see the finished MV appear in History.

Background
The second yco-spec screenshot-first storyboard in the programme (PLAN.md), following the finished AI Song Creation spec. MV is specced as TWO documents (PLAN.md D1) — this one covers /mv/room through /mv/result; /mv/edit is S3.
Goal
Give QA a screenshot-led walkthrough of the MV Creation flow they can follow without cross-referencing code.
Reading this spec. This is a behavior specification for the front-end RD, not production code — the prototype source cannot be reused. Each step card shows the screenshot first, then what the user does (bold) and what the WEB UI shows, with on-screen text, rules & limits, and input/output below. On a screenshot, a solid red frame marks the click that advances the flow; a dashed amber frame marks a key point to note (hover a frame for its label). Steps carry a stable ID (e.g. P1-S2).
PlatformYouCam Muse Web (desktop) — captured at 1440px
AudienceQA
ScopeStoryboard-first end to end (P1), direct generation with Templates only (P2), generation failure at both stages (P3), the six compose sheets and their numeric boundaries (P4), the guest sign-in gate (P5), insufficient credits (P6), the Trending MVs / My Creations side-rail swap (P7), and a controls tour of /mv/result (P8).
Out of scope/mv/edit (MV-P5 in the area spec) — see specs/storyboards/mv-edit (S3, postponed). History’s own behavior (filters, ⋯ menu, publish, delete) — see specs/areas/05-history.md.

P1Storyboard-first — happy path

Compose a brief, review and edit an AI-drafted storyboard, then render. Ends with the new row in History.

  1. P1-S1 Arrives at /mv/room.
  2. P1-S2 Taps the third MV-type card.
  3. P1-S3 Taps Song Library, then hovers the first row.
  4. P1-S4 Taps Use on “My Wedding Ballad”.
  5. P1-S5 Taps Confirm.
  6. P1-S6 Types a description.
  7. P1-S7 Taps a Sample Photo.
  8. P1-S8 Both a song and a description now exist.
  9. P1-S9 Taps Create Music Video.
  10. P1-S10 Taps Create Storyboard First.
  11. P1-S11 The storyboard job finishes.
  12. P1-S12 Scrolls to and taps Generate MV.
  13. P1-S13 Waits for the render to finish.
  14. P1-S14 The render finishes.
  15. P1-S15 Opens History from the sidebar.

P3Generation failure — both stages

A QA hook forces a mid-generation failure at each of the two stages a generation can start from.

  1. P3-S1 Composes a brief whose description contains the “[fail]” marker.
  2. P3-E2 Picks Create Storyboard First; the job fails around 60% progress.
  3. P3-E3 A fresh “[fail]” brief, this time picking Create MV Directly; the job fails around 60% progress.
P3-S1
1
  • 1Create Music Video
TRIGGERComposes a brief whose description contains the “[fail]” marker.
WEB UICreate Music Video becomes enabled, same as any complete brief.
Rules
  • The “[fail]” marker is read once, when the job is first created, and reused when it re-renders.So a storyboard-first job with this marker fails at the STORYBOARD (thinking) stage; a direct job fails at CREATING — never both, and never at the other stage.
P3-E2
⚠ ERRORPicks Create Storyboard First; the job fails around 60% progress.
WEB UI/mv/thinking swaps to a Generation Failed state with Retry and Back.
Strings

  • Body: “Something went wrong while generating. Your credits were not charged — you can retry now or adjust your input and try again.”
  • Buttons: “Retry”, “Back”
Rules
  • Back returns to /mv/room.
  • Retry re-runs the SAME compose, which still contains “[fail]”, so it re-fails deterministically (MV-E1).The copy says “adjust your input” but Retry itself performs no in-place edit; only Back returns to the form to change it (mock-only artifact).
  • The charged storyboard cost is refunded in full on failure (AC-MV-11, AC-MV-19).Matches the on-screen “credits were not charged” message.

    P5Guest sign-in gate

    A signed-out visitor can browse and compose freely; only Song Library and Create Music Video are gated.

    1. P5-S1 A signed-out visitor arrives at /mv/room.
    2. P5-S2 Imports a local audio file, then confirms Trim.
    3. P5-S3 Fills the description, then taps Create Music Video.
    4. P5-S4 Taps a sign-in provider (Apple or Google — both mocked).
    P5-S1
    TRIGGERA signed-out visitor arrives at /mv/room.
    WEB UIRenders the full compose screen with no sign-in modal; the sidebar shows a “Login” control instead of an account menu.
    Rules
    • /mv/room has no route guard (AC-MV-01b).Unlike most authed routes, this screen is the destination of the marketing Navbar’s Start for Free, so a guest must be able to browse and compose before signing in.
    P5-S2
    TRIGGERImports a local audio file, then confirms Trim.
    WEB UIImport Audio works with no sign-in prompt at any point; the song is added like a signed-in session.
    Strings
    • Source label after import: “Imported Audio”
    Rules
    • Import Audio stays ungated even for a guest (AC-MV-01b).A file the user already holds locally is not account data — it is the only song source a guest can use without signing in, since Song Library IS gated.
    P5-S3
    TRIGGERFills the description, then taps Create Music Video.
    WEB UIThe sign-in modal opens over the compose screen; the composed draft stays visible and untouched underneath.
    Strings
    • Title: “Sign in to YouCam Muse”
    • Subtitle: “Save your creations, sync across devices, and unlock your full creative history.”
    • Buttons: “Continue with Apple”, “Continue with Google”
    Rules
    • Reuses the site’s shared sign-in modal (same as the Song spec’s P4-S1).The gate is on the ACTION (Create Music Video, and separately Song Library), never on the route.
    P5-S4
    TRIGGERTaps a sign-in provider (Apple or Google — both mocked).
    WEB UIA brief “Signed in successfully!” stage plays, then the ORIGINAL Create Music Video action resumes automatically.
    Strings
    • Message: “Signed in successfully!” — “Welcome back, Scott · via Apple”
    Rules
    • The guest never returns to a blank compose screen after signing in — the action that opened the modal resumes.Here, that is the mode chooser Create Music Video would have opened.
    • The insufficient-credit check (P6-S1) runs only after sign-in resumes the action, never while still signed out.A guest is never shown the buy-credits upsell for an account they do not have yet.

    ⚠ Prototype Simplifications — NOT the production contract

    Where the prototype fakes or stubs behaviour. Build the production must do column — never the prototype behaviour.

    AreaPrototype doesProduction must do
    BackendOnly `MockMuseApi` exists — there is no real backend anywhere in this repo.A production build swaps in a real API implementing the same `MuseApi` contract; every job, poll, and cost in this spec is the mock’s behavior, not a guarantee about real timing or exact pricing.
    Generation timingThe mock resolves a storyboard or render job in a few seconds of wall-clock time, regardless of the on-screen “~1 minute” / “~2 minutes” estimates.Real generation duration is backend-determined; the on-screen estimates must reflect the actual expected wait or be removed.
    In-memory History and creditsBoth the History list and the credit balance are in-memory React state that resets to its default on every full page load (confirmed live in P7: reloading /mv/room puts the side rail back to Trending even right after generating an MV).A real balance and History are server-held and must survive a reload; the charge must be atomic with the generation request rather than applied client-side before it.
    Seeded librariesMy Songs (2), Sample Songs (5), Sample Photos (8), and Templates (6) are all static fixture arrays in `src/lib/mv/mock.ts`, not a real per-account library or a CMS-fed catalog.Production needs a real per-account song/photo library and a CMS-authored template catalog; an always-populated Choose Song also means the intended empty-state (TBD-MV-11) is unbuilt and unverifiable here.
    MV-E1’s deterministic re-failThe “[fail]” marker is a QA-only hook with no production trigger; Retry re-runs the identical compose and therefore re-fails every time, which is why the on-screen “adjust your input” copy has no matching affordance in this build.A real failure needs a real trigger (timeout, model error, moderation reject, …); production Retry should reasonably succeed once whatever caused the failure has cleared.
