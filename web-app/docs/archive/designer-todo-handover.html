怎麼讀這份文件

每一項都標了是否擋開發。多數不擋 —— 工程端會照現況繼續搬，搬到了再回頭補。 每一項底下的紫色框是需要你回覆的那一個問題，其餘是背景說明。

一個共通原則：designer-prototype/ 底下的 CSS 在工程端是逐位元組複製的， 所以「在工程端先改一下」等於下次交稿會被覆蓋回去。凡是顏色、尺寸、版位的決定，都要回到設計稿改。

A. 擋開發的兩項

擋 A5 — 手機上 detail 畫面沒有任何返回途徑

AppLayout.css 在 <767px 把 .detail-navbar 等整批 display:none，而 MobileHeader 沒有 back 控制項。 結果是手機上進得去、出不來。

把 DP 跑在 375px 逐頁量「宣告了 back 但算出來高度是 0」，命中 5 個畫面：

DP 畫面對應 route375px 實測
MVDetailPage/watchdeclared=1 visible=0
AccountPage(settings)/settingsdeclared=1 visible=0
CommunityProfilePage/creatordeclared=1 visible=0
MVResultPage/mv/resultdeclared=1 visible=0
MVStoryboardPage/mv/storyboarddeclared=1 visible=0

SongDetailPage 是唯一的例外，它自帶一個有返回鍵的全螢幕手機播放器 —— 那正是這題想要的答案的範例，只是沒有推廣到其他畫面。

工程端已止血 已在自家的 DetailNavbar 元件加一顆手機專用返回鍵（預設開啟，所以新畫面不會被關住）， 底欄可達的畫面明確關閉。一個檔案、一個刪除點，你給稿後即可移除。

需要你決定：手機 detail 畫面的返回鍵放哪裡？ （MobileHeader 加 back？detail-navbar 手機只留 back 一顆？還是把 SongDetailPage 的頁內返回鍵推廣成通則？）

需要你決定（擇一）：調整處理方式（加深底色 / 改深色文字 / 字級加大到 ≥18px 讓門檻降為 3:1 / 提高不透明度）， 或明確接受這組例外。

會靜默壞掉 A2 — 四個 token 在 tokens.css 裡不存在

--neutral-dark-48、--neutral-dark-15、 --line-height-body-s、--font-weight-regular 被引用但從未定義。

這是 CSS 最危險的失敗方式：沒有錯誤、沒有警告、build 照過，元素只是安靜地換了樣子。 工程端已加自動掃描，之後每次交稿會立刻抓到。

需要你決定：這四處原本想用哪個值？是打錯字（48 → 44 或 54？），還是 tokens 少了這幾階？

手機版 A8 / A10 / A14 — 手機上的可用性問題

  • A8：TopSongListItem.css 一條 media query 都沒有。320px 標題只剩 1–2 個字元（「P…」「C…」），375px 約 10 字。手機上這份清單是 Explore 的頂層目的地。
  • A14：.mv-player__title 在 375px 截斷成「Cinemat…」，成因同上。
  • A10：6 個控制項小於 24×24（WCAG 2.5.8 AA）：toggle-switch__track 36×20、mv-create__idea-btn 79×20、mv-result__control-btn 20×20、song-create__idea-btn 51×20、History 兩個 <a> 高 18。

好消息一併回報：DP 在 320 / 375 沒有任何水平溢出，12 條 route 全部量過。版面本身是會縮的。

需要你決定：(1) 320–767px 的 song list 與 player title 怎麼排？請給手機 frame。 (2) 那 6 個控制項要放大到 24，還是靠加大 hit area（padding / ::after，不動視覺）？

取捨 A6 / A7 / A14 — 稿與 spec 的落差

  • A7：DP 的 transport 沒有 shuffle / repeat，但 spec AC-EXP-05 明文要求。產品已拍板照 DP，所以現在 code 是刻意違反 spec 的狀態。
  • A6：SongDetailPage 的 Trending tab 沒有對應資料（稿子自己的註解就說明那是假的）。工程端先不做這個 tab。
  • A14：/watch 移轉後少了 4 個區塊：# Music Video 標籤、meta 行、統計（plays/likes/shares）、來源 prompt。已逐條比對 AC-EXP-04，四者都不在任何 AC 裡，所以不是 spec 違規，但 /watch 因此變成純播放器。
需要你決定：A7 請確認 shuffle/repeat 是刻意拿掉；A6 請說明 Trending 要餵什麼資料； A14 若要保留統計 / prompt，請給一個能放它們的版位。

數值 D — 需要對齊的兩個數字

  • S20：DP 的 UpgradeDialog 寫 $9.99，程式碼是 $19.99。已拍板以程式碼為準，請下次交稿對齊（其餘兩檔一致）。
  • S2：spec 要求 MV 音訊 30 秒下限並顯示提示；DP 的 TrimAudioSheet 只有相對比例下限，沒有絕對秒數。已拍板保留 30 秒，需要對應的錯誤提示視覺。

需要你決定：30 秒下限的錯誤提示、以及餘額不足 / 歸零的狀態，各需要一張稿。

其他 A3 / A4 / A12

  • A3：HistoryPage.css 的斷點是 480 / 767 / 900 / 1200，與議定的六階（320 / 375 / 768 / 1024 / 1440 / 1920）只有 767 對得上。是刻意還是疏漏？
  • A4：AppLayout.css 的手機規則把 navbar 的 tabs 列一起藏掉，導致 History 的篩選（含有 spec 的 Liked）在手機上整組消失。判斷是疏漏 —— 因為 RoomNavbar.css 自己就為那一列寫了手機樣式，只是被蓋掉了。工程端已用 override 暫時放回。請下次交稿讓 tabs 列在 <767px 保持顯示。
  • A12：交付的 DP 副本跑不起來（缺 25 個媒體檔，vite 在 import 階段就失敗）。工程端補 stub 後 12/14 條可跑，但 /song-detail 與 /mv-edit 連桌機都是白畫面。/mv/edit 的手機狀況因此沒有任何人看過。
